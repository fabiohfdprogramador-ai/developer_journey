📖 Ler os Mestres e Contribuir

As duas práticas que aceleram o fim da curva: ler código de gente grande e contribuir com open source — com protocolo, não com boa intenção.

1. Ler Código-Fonte (1 Sessão/Semana, para sempre)

Onde começar

  • Redis: C limpo, comentado, tamanho abarcável
  • PostgreSQL: módulos (parser, executor)
  • Runtime de Go: trechos do scheduler e GC
  • Utilitários Unix: ferramentas clássicas

Protocolo de leitura

  1. Escolha UMA pergunta ("como o Redis trata um GET?")
  2. Entre pela main/handler
  3. Siga o fluxo com caderno, desenhando as estruturas
  4. Escreva um resumo de 10 linhas

💡 Ler sem pergunta é turismo; com pergunta é treino.

✅ O ganho composto: você absorve padrões de projeto reais e perde o medo de "código dos outros".

2. Open Source (O Code Review que Ensina de Graça)

A escada do open source

  1. Usar → conhecer a ferramenta
  2. Reportar bug bem escrito (mínimo reproduzível!)
  3. Documentação e testes
  4. Good first issue
  5. Bugfix
  6. Feature pequena

Alvos naturais

  • Ferramentas que você já usa (NestJS, libs Go, K8s ecosystem)
  • Leia o CONTRIBUTING
  • PR pequeno, descrição honesta
  • Paciência com o review — mantenedor é mentoria gratuita

💡 Meta do bloco: 3 PRs aceitos em projetos reais.

📝 Exercícios — 25 questões

1. Por que ler código-fonte de projetos grandes é importante?
✅ Correta! Absorve padrões de projeto reais, perde o medo de código alheio e melhora sua própria escrita.
2. Qual a diferença entre ler código "por turismo" e "com pergunta"?
✅ Correta! Turismo: ler sem objetivo; com pergunta: foco direcionado que gera aprendizado.
3. Qual a escada de contribuição em open source?
✅ Correta! Usar → reportar bug → docs/testes → good first issue → bugfix → feature pequena.
4. Como escrever um bom reporte de bug?
✅ Correta! Mínimo reproduzível, descrição clara, logs, versão do software.
5. Qual a meta de PRs aceitos neste bloco?
✅ Correta! 3 PRs aceitos em projetos reais.
6. O que é open source?
✅ Correta! Código fonte disponível publicamente para uso, modificação e distribuição.
7. O que é contribuição open source?
✅ Correta! Qualquer trabalho (código, docs, testes, bug reports) adicionado a um projeto open source.
8. O que é good first issue?
✅ Correta! Issue em projetos open source marcada como adequada para iniciantes.
9. O que é CONTRIBUTING em projetos open source?
✅ Correta! Guia de contribuição do projeto, com regras e processo de PR.
10. O que é code review?
✅ Correta! Processo de revisão de código por outros desenvolvedores antes do merge.
11. O que é pull request (PR)?
✅ Correta! Requisição para mesclar mudanças de uma branch para outra em um repositório Git.
12. O que é fork no contexto do GitHub?
✅ Correta! Cópia de um repositório para sua conta, permitindo contribuições sem permissão direta.
13. O que é CLA (Contributor License Agreement)?
✅ Correta! Acordo legal que define os direitos do contribuidor sobre o código.
14. O que é DCO (Developer Certificate of Origin)?
✅ Correta! Certificado que o contribuidor tem direito a enviar o código.
15. O que é LICENSE em um projeto open source?
✅ Correta! Arquivo que define os termos de uso, modificação e distribuição do código.
16. O que é MIT License?
✅ Correta! Licença permissiva que permite uso, modificação e distribuição.
17. O que é GPL License?
✅ Correta! Licença copyleft que exige que derivativos também sejam open source.
18. O que é Apache License?
✅ Correta! Licença permissiva com proteção de patentes.
19. O que é maintainer em open source?
✅ Correta! Responsável por manter o projeto, revisar PRs e gerenciar issues.
20. O que é contributor em open source?
✅ Correta! Quem contribui com código, documentação ou qualquer trabalho para o projeto.
21. O que é issue tracker?
✅ Correta! Sistema de gerenciamento de tarefas, bugs e solicitações (ex: GitHub Issues).
22. O que é README?
✅ Correta! Arquivo de documentação principal do projeto.
23. O que é CHANGELOG?
✅ Correta! Registro de mudanças e versões do projeto.
24. O que é semantic versioning (SemVer)?
✅ Correta! Sistema de versionamento MAJOR.MINOR.PATCH (ex: 2.1.3).
25. Qual a importância de contribuir com open source para um(a) engenheiro(a)?
✅ Correta! Aprende com mentores, constrói portfólio, entende código de produção real.
