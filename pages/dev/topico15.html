🌐 Redes: Da Tomada ao HTTPS

O modelo em camadas, IP/TCP, HTTP por dentro, DNS e TLS — com as ferramentas (curl, dig) que transformam "a internet caiu" em diagnóstico de 2 minutos.

1. O Modelo em Camadas (Prático de 4)

CamadaProtagonistasResponsabilidade
AplicaçãoHTTP, DNS, TLS, MQTTo significado das mensagens
TransporteTCP, UDPentregar ao processo certo (portas), confiabilidade

Enlace/físicaEthernet, Wi-Fibits no meio físico local

Cada camada só conversa com as vizinhas — encapsulamento permite trocar Wi-Fi por cabo sem o HTTP saber.

2. IP e TCP

IP

  • Endereços: 192.168.0.10
  • Sub-redes: CIDR (/24 = 256 endereços)
  • Roteamento salto a salto
  • NAT: muitos privados atrás de um público

UDP

Datagramas sem garantia — rápido, para DNS, streaming, telemetria tolerante a perda.

TCP

  • Conexão com handshake de 3 vias (SYN → SYN-ACK → ACK)
  • Entrega ordenada e confiável (ACKs + retransmissão)
  • Controle de fluxo e congestionamento

Portas: 22 SSH, 80 HTTP, 443 HTTPS, 5432 Postgres, 1883 MQTT.

3. HTTP Por Dentro

GET /api/users/42 HTTP/1.1
Host: api.exemplo.com
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{"id": 42, "name": "Ana"}

Métodos

  • GET (ler), POST (criar), PUT/PATCH (atualizar), DELETE
  • GET/PUT/DELETE são idempotentes — repetir não muda o resultado

Status

2xx ok · 3xx redireciona · 4xx erro do cliente · 5xx erro do servidor

Evolução

HTTP/1.1 (texto, 1 req por vez) → HTTP/2 (binário, multiplexado) → HTTP/3 (QUIC sobre UDP)

4. DNS e TLS

DNS

Traduz nome → IP: resolver → raiz → TLD (.com) → autoritativo.

  • Registros: A/AAAA (IP), CNAME (apelido), MX, TXT
  • TTL: tempo de cache (por isso mudança de DNS "demora a propagar")

TLS

Dá o S do HTTPS:

  • Handshake com certificado (servidor prova quem é, assinado por uma CA)
  • Acordo de chaves → canal simétrico cifrado
  • Garante: confidencialidade + integridade + autenticidade

5. A Caixa de Ferramentas

curl -v https://api.exemplo.com/health   # requisição com bastidores
dig api.exemplo.com                      # resolução DNS
ping 8.8.8.8 && traceroute 8.8.8.8      # alcance e rota
ss -tlnp                                 # portas abertas e quem escuta
tcpdump -i any port 5432 -w cap.pcap    # capturar tráfego

📝 Exercícios — 25 questões

1. Ordene o que acontece ao abrir https://site.com: handshake TCP, consulta DNS, handshake TLS, requisição HTTP.
✅ Correta! DNS → TCP → TLS → HTTP
2. Por que DNS usa UDP na consulta comum? E por que TCP existe como alternativa?
✅ Correta! Consulta pequena, 1 ida e volta, perda tolerável (repete); TCP para respostas grandes/transferência de zona.
3. POST é idempotente? E PUT? Por que isso importa para retry automático?
✅ Correta! POST não (cria de novo); PUT sim (mesmo estado final) — retry seguro exige idempotência ou chave de deduplicação.
4. Quantos hosts úteis tem um /24? O que o NAT resolve?
✅ Correta! 254 (rede + broadcast fora); NAT: escassez de IPv4, muitos privados atrás de 1 público.
5. Um curl -v mostra "connection refused" vs "timeout": o que cada um sugere?
✅ Correta! Refused: chegou e a porta está fechada (serviço parado); timeout: nada respondeu (firewall/rota/host fora).
6. Explique TTL do DNS e seu efeito numa migração de servidor.
✅ Correta! Tempo de cache da resposta: TTL alto atrasa a virada; baixe o TTL antes de migrar.
7. O que é TCP handshake de 3 vias?
✅ Correta! SYN → SYN-ACK → ACK: estabelecimento da conexão TCP.
8. Qual a diferença entre TCP e UDP?
✅ Correta! TCP: orientado a conexão, confiável, ordenado; UDP: sem conexão, não confiável, mais rápido.
9. O que é porta em redes?
✅ Correta! Número que identifica um processo/serviço em um host (ex: 80 para HTTP).
10. O que é DNS?
✅ Correta! Sistema que traduz nomes de domínio para endereços IP.
11. O que é TLS?
✅ Correta! Protocolo que garante comunicação segura na internet (criptografia, autenticação, integridade).
12. O que é HTTP?
✅ Correta! Protocolo de transferência de hipertexto — base da World Wide Web.
13. Qual a diferença entre HTTP e HTTPS?
✅ Correta! HTTPS = HTTP + TLS (criptografia).
14. O que é NAT?
✅ Correta! Tradução de endereço de rede: permite múltiplos dispositivos compartilharem um IP público.
15. O que é sub-rede (subnet)?
✅ Correta! Divisão lógica de uma rede IP.
16. O que é CIDR?
✅ Correta! Notação para sub-redes: 192.168.0.0/24.
17. O que é pacote (packet)?
✅ Correta! Unidade de dados transmitida em uma rede.
18. O que é firewall?
✅ Correta! Sistema que controla o tráfego de rede baseado em regras de segurança.
19. O que é proxy?
✅ Correta! Servidor intermediário que encaminha requisições entre cliente e servidor.
20. O que é CDN (Content Delivery Network)?
✅ Correta! Rede distribuída de servidores que entrega conteúdo com baixa latência.
21. O que é WebSocket?
✅ Correta! Protocolo que mantém conexão bidirecional persistente entre cliente e servidor.
22. O que é gRPC?
✅ Correta! Framework RPC de alto desempenho usando HTTP/2 e Protobuf.
23. O que é MQTT?
✅ Correta! Protocolo leve de mensageria para IoT, baseado em publish/subscribe.
24. O que é latência em redes?
✅ Correta! Tempo que um pacote leva para viajar da origem ao destino.
25. O que é banda (bandwidth)?
✅ Correta! Capacidade máxima de transmissão de dados em uma rede.
