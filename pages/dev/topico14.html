🖥️ Sistemas Operacionais

Processos e threads, memória virtual e concorrência (race conditions e deadlocks) — o que está por trás de containers, event loops e daquele OOMKilled do Kubernetes.

1. Processos

Um processo = programa em execução: memória própria (código, dados, heap, stack), descritores de arquivo, PID.

  • O kernel alterna processos na CPU milhares de vezes por segundo (escalonamento preemptivo)
  • Criar processo: fork() (clona o atual) + exec() (substitui pelo novo programa)
  • Sinais: kill -TERM pid pede para terminar; -KILL não pede

Ferramentas: ps aux, top, strace ./app (todas syscalls do programa).

2. Threads e o Porquê do Async

  • Threads: dividem a memória do processo (baratas de criar, comunicação trivial — e perigosa)
  • Event loop (Node.js): 1 thread + I/O não bloqueante — ótimo para muitas conexões esperando rede, ruim para CPU pesada
  • Goroutines (Go): milhares de "threads leves" multiplexadas em poucas threads reais

3. Memória Virtual

Cada processo enxerga um espaço de endereços próprio e contínuo — mentira útil mantida pelo kernel + MMU.

  • Page fault: carrega páginas sob demanda
  • Swap: empurra páginas frias para disco (latência explode)
  • OOM killer: sem memória, o kernel mata alguém

⚠️ Processo isolado: um processo não lê a memória do outro.

4. Concorrência — A Race Condition

/* duas threads executam: contador++; */
/* contador++ é na verdade: LER → SOMAR 1 → ESCREVER */

Duas threads leem 5 ao mesmo tempo, ambas escrevem 6 — um incremento se perde. Isso é uma race condition.

Mutex — Exclusão Mútua

pthread_mutex_lock(&m);
contador++;  /* só uma thread por vez aqui */
pthread_mutex_unlock(&m);

Deadlock

T1 segura A e quer B; T2 segura B e quer A — ninguém anda.

💡 Prevenção: todos adquirem locks na mesma ordem.

Ferramentas: sanitizers (-fsanitize=thread) e, em Go, -race.

📝 Exercícios — 25 questões

1. Processo x thread: memória, custo de criação, riscos.
✅ Correta! Processo: memória isolada, criação cara, seguro; thread: memória compartilhada, barata, sujeita a races.
2. O que fork() retorna no pai e no filho? Como o shell usa isso?
✅ Correta! PID do filho no pai; 0 no filho — o shell faz fork, o filho dá exec no comando, o pai espera (wait).
3. Seu Node trava ao calcular um hash pesado. Explique com o modelo do event loop.
✅ Correta! CPU pesada na única thread bloqueia todos os callbacks pendentes.
4. Duas threads fazem x = x + 1 1000 vezes cada, sem lock. Por que o resultado pode ser < 2000?
✅ Correta! Incrementos não são atômicos: leituras simultâneas perdem escritas (race condition).
5. Descreva um deadlock com locks A e B e a regra que o previne.
✅ Correta! T1: lock(A)→quer B; T2: lock(B)→quer A. Regra: ordem global de aquisição (sempre A antes de B).
6. Seu pod morreu com OOMKilled. O que aconteceu, em termos de kernel?
✅ Correta! Container passou do limite de memória; o kernel (OOM killer) matou o processo.
7. O que é escalonamento preemptivo?
✅ Correta! O kernel interrompe um processo para dar CPU a outro, criando a ilusão de simultaneidade.
8. O que é syscall (chamada de sistema)?
✅ Correta! Interface que um programa usa para solicitar serviços ao kernel (ex: ler arquivo, alocar memória).
9. O que é memória virtual?
✅ Correta! Abstração que dá a cada processo seu próprio espaço de endereços contínuo.
10. O que é page fault?
✅ Correta! Interrupção quando um processo acessa uma página que não está na RAM.
11. O que é swap?
✅ Correta! Área em disco usada como extensão da memória RAM.
12. O que é race condition?
✅ Correta! Quando o resultado de um programa depende da ordem imprevisível de execução de threads.
13. O que é deadlock?
✅ Correta! Situação onde dois ou mais processos ficam bloqueados permanentemente, cada um esperando por um recurso que o outro possui.
14. O que é semáforo?
✅ Correta! Mecanismo de sincronização que controla acesso a recursos compartilhados.
15. O que é mutex?
✅ Correta! Mecanismo de exclusão mútua que garante que apenas uma thread acesse um recurso por vez.
16. Qual a diferença entre concorrência e paralelismo?
✅ Correta! Concorrência: múltiplas tarefas em progresso (alternando); Paralelismo: múltiplas tarefas executando ao mesmo tempo (múltiplos cores).
17. O que é context switch?
✅ Correta! Troca do estado de um processo/thread para outro pela CPU.
18. O que é interrupção (interrupt)?
✅ Correta! Sinal enviado ao processador para interromper a execução atual e atender a um evento.
19. O que é kernel?
✅ Correta! Núcleo do sistema operacional que gerencia hardware, processos, memória e I/O.
20. O que é modo usuário e modo kernel?
✅ Correta! Modo usuário: execução com privilégios limitados; Modo kernel: execução com privilégios totais (acesso ao hardware).
21. O que é POSIX?
✅ Correta! Padrão de interfaces para sistemas operacionais compatíveis com Unix.
22. O que é thread-safe?
✅ Correta! Código que funciona corretamente quando executado por múltiplas threads simultaneamente.
23. O que é barreira (barrier) em programação concorrente?
✅ Correta! Ponto de sincronização onde threads esperam até que todas cheguem.
24. O que é starvation?
✅ Correta! Quando uma thread nunca recebe o recurso que precisa para executar.
25. O que é livelock?
✅ Correta! Processos estão ativos mas não progridem, ficando em um loop de tentativas frustradas.
