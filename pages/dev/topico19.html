🔗 Backend Avançado: APIs, Auth e Mensageria

REST maduro, gRPC no lugar certo, autenticação sem copiar-e-colar (JWT/OAuth2/OIDC) e mensageria com as garantias reais — idempotência e outbox incluídos.

1. REST Maduro (e quando gRPC)

Recursos e Verbos

GET /orders/42
POST /orders
PATCH /orders/42
DELETE /orders/42
  • Status corretos: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found, 500 Internal Server Error
  • Erros com corpo útil: código + mensagem + correlation id
  • Paginação: cursor > offset para listas vivas
  • Versionamento: /v1/api
  • Rate limiting: 429 + Retry-After

gRPC

  • Contratos protobuf + HTTP/2
  • Ideal entre serviços (tipado, rápido, streaming)
  • REST/JSON segue rei na borda pública

GraphQL

Quando o cliente precisa compor consultas flexíveis (mobile/BFF).

2. Autenticação e Autorização de Verdade

Sessão + Cookie

  • Estado no servidor
  • Simples, revogável
  • Ótimo para web clássica

JWT (JSON Web Token)

HEADER: { "alg": "HS256", "typ": "JWT" }
PAYLOAD: { "sub": "user123", "exp": 1690000000, "roles": ["admin"] }
SIGNATURE: HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)
  • Token assinado com claims (sub, exp, roles)
  • Servidor valida a assinatura sem consultar banco → stateless
  • ⚠️ Revogação difícil → vida curta (minutos) + refresh token
  • ⚠️ Payload é só codificado, não cifrado — não guarde segredos!

OAuth2

  • Delegação — "entrar com Google"
  • Papéis: resource owner (você), client (app), authorization server (Google), resource server (API)
  • Fluxo padrão: Authorization Code + PKCE

OIDC (OpenID Connect)

Camada de identidade sobre OAuth2 (id_token que diz quem você é).

💡 AuthN ≠ AuthZ: Autenticar é saber quem é; Autorizar é decidir o que pode (roles/policies no servidor, sempre).

3. Mensageria — Desacoplando com Filas e Tópicos

Fila vs Tópico

  • Fila (RabbitMQ/SQS): tarefa para um worker consumir (work queue)
  • Tópico/Log (Kafka/NATS): evento publicado para vários consumidores independentes, com replay

Garantias

  • Padrão real: at-least-once — mensagem pode chegar duas vezes (timeout + retry)
  • "Exactly-once" fim a fim = at-least-once + idempotência sua

Idempotência

INSERT INTO processed_events(event_id) VALUES ('evt-123')
ON CONFLICT (event_id) DO NOTHING;

Outbox Pattern

BEGIN;
INSERT INTO orders (...) VALUES (...);
INSERT INTO outbox (event_id, type, payload) VALUES (...);
COMMIT;
-- Relay publica os eventos para o broker
  • Resolve o dilema "salvei no banco mas caí antes de publicar"
  • Evento gravado na mesma transação → broker eventualmente consistente

Higiene de Consumo

  • Retries com backoff + DLQ (Dead Letter Queue) para mensagens venenosas
  • Consumidores lentos = lag monitorado

📝 Exercícios — 25 questões

1. Desenhe o fluxo Authorization Code (com PKCE) em 6 passos.
✅ Correta! App → auth server (redirect + code_challenge) → login/consentimento → code → app troca code+verifier por tokens → API valida access token.
2. Por que JWT de 24 h sem refresh é um risco? Qual o desenho recomendado?
✅ Correta! Roubo do token vale 24 h sem revogação; use access curto (5-15 min) + refresh revogável.
3. Fila x tópico: dois casos de uso claros para cada.
✅ Correta! Fila: jobs de e-mail, processamento de imagem; Tópico: eventos de domínio para N consumidores, telemetria com replay.
4. Seu consumer morreu após processar e antes do ACK. O que acontece no restart e o que protege o sistema?
✅ Correta! Mensagem volta (sem ACK) e reprocessa — a idempotência absorve a duplicata.
5. Especifique a tabela outbox (colunas) e o papel do relay.
✅ Correta! Colunas: id, aggregate_id, type, payload, created_at, published_at; relay lê não publicados, publica no broker, marca.
6. POST /orders com retry automático do cliente: que header/mecanismo evita pedido duplicado?
✅ Correta! Idempotency-Key por tentativa lógica + tabela de deduplicação no servidor.
7. O que é REST?
✅ Correta! Estilo arquitetural para APIs baseado em recursos e verbos HTTP.
8. O que é gRPC?
✅ Correta! Framework RPC de alto desempenho usando HTTP/2 e Protobuf.
9. O que é GraphQL?
✅ Correta! Linguagem de consulta para APIs que permite clientes solicitarem exatamente os dados que precisam.
10. O que é JWT?
✅ Correta! JSON Web Token: token assinado usado para autenticação e autorização.
11. O que é OAuth2?
✅ Correta! Framework de autorização que permite delegação de acesso sem compartilhar credenciais.
12. O que é OIDC (OpenID Connect)?
✅ Correta! Camada de identidade sobre OAuth2 que adiciona autenticação.
13. Qual a diferença entre autenticação e autorização?
✅ Correta! Autenticação: verificar identidade ("quem é você?"); Autorização: verificar permissões ("o que você pode fazer?").
14. O que é Kafka?
✅ Correta! Plataforma de streaming distribuída para processamento de eventos em tempo real.
15. O que é RabbitMQ?
✅ Correta! Message broker que implementa AMQP para filas e roteamento de mensagens.
16. O que é idempotência?
✅ Correta! Propriedade de uma operação onde o resultado é o mesmo independente de quantas vezes é executada.
17. O que é Outbox Pattern?
✅ Correta! Padrão onde eventos são salvos na mesma transação do banco e publicados posteriormente por um relay.
18. O que é DLQ (Dead Letter Queue)?
✅ Correta! Fila para mensagens que não puderam ser processadas (venenosas).
19. O que é rate limiting?
✅ Correta! Controle de quantidade de requisições que um cliente pode fazer em um período.
20. O que é HTTP/2?
✅ Correta! Versão do HTTP com multiplexação, compressão de headers e server push.
21. O que é HTTP/3?
✅ Correta! Versão do HTTP baseada em QUIC (UDP), com melhor performance e menor latência.
22. O que é websocket?
✅ Correta! Protocolo que mantém conexão bidirecional persistente entre cliente e servidor.
23. O que é correlation id em APIs?
✅ Correta! Identificador único que rastreia uma requisição através de múltiplos serviços.
24. O que é backoff em retries?
✅ Correta! Aumento progressivo do tempo de espera entre tentativas de retry (ex: exponencial).
25. O que é jitter em retries?
✅ Correta! Variação aleatória no tempo de espera para evitar thundering herd (todos retentando ao mesmo tempo).
