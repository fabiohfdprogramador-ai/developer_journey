📊 Observabilidade — Enxergar o Sistema

Os 3 pilares (métricas, logs, traces), os métodos RED/USE, e SLI/SLO com error budget — confiabilidade tratada com números, não com adrenalina.

1. Os Três Pilares

📈 Métricas

Números agregados no tempo — baratas, para alertar e ver tendência. Prometheus.

📋 Logs

Eventos com contexto — para investigar o caso específico. Sempre com trace_id.

🔍 Traces

A jornada de UMA requisição pelos serviços — onde os 800 ms se esconderam. OpenTelemetry.

💡 Instrumente com OTel uma vez, exporte para o backend que quiser — padrão aberto.

2. O Que Medir

RED (serviços)

  • Rate: req/s
  • Errors: % de erros
  • Duration: latência por percentil (p50/p95/p99)

USE (recursos)

  • Utilization: uso (%)
  • Saturation: fila/espera
  • Errors: falhas

Dashboard bom responde "está saudável?" em 5 segundos.

3. SLI, SLO e Error Budget

  • SLI: o indicador medido (ex.: % de requisições < 300 ms e sem 5xx)
  • SLO: a meta (99,9% no mês)
  • Error budget: 100% – SLO = quanto pode falhar (99,9% = ~43 min/mês)

📝 Exercícios — 25 questões

1. p50 = 80 ms e p99 = 2 s: o que isso diz que a média esconderia?
✅ Correta! 1% dos usuários sofre 25× a latência típica — cauda longa invisível na média.
2. Monte o RED de um endpoint de checkout (métricas concretas + 1 alerta).
✅ Correta! rate por status, taxa de 5xx, histograma de duração; alerta: erro > 1% por 5 min.
3. SLO 99,5%/mês: qual o error budget em minutos (~30 dias)?
✅ Correta! 0,5% de 43.200 min ≈ 216 min
4. Por que "CPU > 80%" costuma ser alerta ruim e "p95 > 500 ms por 10 min" costuma ser bom?
✅ Correta! CPU alta pode ser saudável (throughput!); latência de usuário é sintoma real.
5. Qual pilar te leva do sintoma ("checkout lento") ao culpado ("consulta X no serviço Y")?
✅ Correta! Tracing (com trace_id ligando logs).
6. O que é observabilidade?
✅ Correta! Capacidade de entender o estado interno de um sistema a partir de seus outputs (métricas, logs, traces).
7. O que é métrica?
✅ Correta! Dado numérico agregado ao longo do tempo (ex: requisições por segundo).
8. O que é log?
✅ Correta! Evento discreto com timestamp e contexto.
9. O que é trace?
✅ Correta! Jornada completa de uma requisição através de múltiplos serviços.
10. O que é Prometheus?
✅ Correta! Sistema de monitoramento e alerta com coleta de métricas por scraping.
11. O que é Grafana?
✅ Correta! Ferramenta de visualização de dados (dashboards).
12. O que é OpenTelemetry?
✅ Correta! Framework de observabilidade para coletar métricas, logs e traces.
13. O que é SLI (Service Level Indicator)?
✅ Correta! Métrica que indica o nível de serviço (ex: latência, disponibilidade).
14. O que é SLO (Service Level Objective)?
✅ Correta! Meta para o SLI (ex: 99,9% de disponibilidade).
15. O que é error budget?
✅ Correta! Quantidade de falhas permitida dentro do SLO.
16. O que é percentil (p50, p95, p99)?
✅ Correta! Valor abaixo do qual X% das observações se encontram (p95 = 95% são menores que esse valor).
17. O que é RED method?
✅ Correta! Método para monitorar serviços: Rate, Errors, Duration.
18. O que é USE method?
✅ Correta! Método para monitorar recursos: Utilization, Saturation, Errors.
19. O que é alerta em observabilidade?
✅ Correta! Notificação acionada quando uma métrica ultrapassa um limite.
20. O que é dashboard?
✅ Correta! Tela com visualizações das métricas do sistema.
21. O que é trace_id?
✅ Correta! Identificador único que correlaciona logs e traces de uma requisição.
22. O que é log structured (log estruturado)?
✅ Correta! Logs em formato estruturado (JSON) para facilitar busca e análise.
23. O que é latência?
✅ Correta! Tempo de resposta de uma requisição.
24. O que é throughput?
✅ Correta! Quantidade de requisições processadas por unidade de tempo.
25. O que é availabilty (disponibilidade)?
✅ Correta! Percentual de tempo que o sistema está operacional.
