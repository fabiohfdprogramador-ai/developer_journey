🏛️ System Design — Um Projeto Trabalhado

O método de projetar sistemas — requisitos → estimativas → desenho → gargalos → evolução — aplicado do início ao fim num encurtador de URLs.

1. Requisitos e Estimativas (5 Minutos que Mudam Tudo)

Funcionais

  • Criar URL curta
  • Redirecionar
  • Expiração opcional
  • Métricas de cliques

Não-funcionais

  • Leitura ≫ escrita (100:1)
  • Redirect p99 < 50 ms
  • 99,95% disponível

Números

  • 10 M novas URLs/mês ≈ 4 escritas/s
  • Leituras ≈ 400/s (pico 10× = 4.000/s)
  • 5 anos: 600 M registros × ~500 B ≈ 300 GB

Um Postgres dá conta do dado; o desafio é a latência de leitura.

2. O Desenho

Escrita

  • POST /urls → gera código de 7 chars base62 (62⁷ ≈ 3,5 trilhões)
  • Colisão desprezível com geração aleatória + UNIQUE constraint e retry
  • Grava (code, url, expires_at)

Leitura

  • GET /{code} → cache primeiro (Redis, cache-aside, TTL 24 h)
  • Miss → Postgres → HTTP 301/302

Contagem de Cliques

  • Não escreva no banco por clique (mataria a escrita)
  • Publique evento click no tópico (Kafka/NATS)
  • Agregue em lote no colunar

Infra

  • Stateless API × N réplicas
  • Redis, Postgres com réplica de leitura
  • RED + tracing

3. Gargalos e Evolução

  • Redis caiu? Cache-aside degrada para o banco (mais lento, mas vivo)
  • Postgres saturou leitura? Réplicas
  • Escrita? Só então particionar por hash(code)
  • Multi-região: redirects na borda (CDN/edge cache) resolvem 90%

💡 O método é o produto: requisitos → números → componentes com justificativa → modos de falha → evolução.

📝 Exercícios — 25 questões

1. Refaça as estimativas para 100× a escala. O que muda primeiro: banco, cache ou app?
✅ Correta! App é stateless (escala fácil); cache absorve leitura; o primeiro a doer é a escrita no Postgres (~400/s ainda ok; em 100× revise geração de IDs e particionamento).
2. Por que 301 (permanente) × 302 (temporário) muda a contagem de cliques? Qual usar aqui?
✅ Correta! 301 é cacheado pelo navegador → cliques futuros nem chegam a você; use 302 se métricas importam.
3. Desenhe (papel) o fluxo do clique com cache hit e com miss, incluindo o evento de métrica.
✅ Correta! hit: api → redis → 302 (+ evento async); miss: api → redis(∅) → pg → popula redis → 302 (+ evento).
4. Aplique o método completo (5 passos) a: "sistema de ingestão de telemetria de 100 k dispositivos".
✅ Correta! livre — critérios: escrita ≫ leitura (inverte o encurtador!), fila na frente, agregação colunar, retenção por camadas.
5. O que é system design?
✅ Correta! Processo de projetar sistemas escaláveis, confiáveis e eficientes.
6. O que é requisito funcional?
✅ Correta! O que o sistema deve fazer (funcionalidades).
7. O que é requisito não-funcional?
✅ Correta! Como o sistema deve ser (performance, disponibilidade, segurança).
8. O que é throughput em system design?
✅ Correta! Quantidade de requisições que o sistema pode processar por unidade de tempo.
9. O que é latência em system design?
✅ Correta! Tempo que uma requisição leva para ser processada.
10. O que é disponibilidade (availability)?
✅ Correta! Percentual de tempo que o sistema está operacional (ex: 99,9%).
11. O que é escalabilidade (scalability)?
✅ Correta! Capacidade do sistema de lidar com aumento de carga.
12. O que é vertical scaling (scale up)?
✅ Correta! Aumentar os recursos de uma máquina (CPU, RAM).
13. O que é horizontal scaling (scale out)?
✅ Correta! Adicionar mais máquinas ao sistema.
14. O que é cache-aside?
✅ Correta! Padrão de cache onde a aplicação lê do cache e popula em caso de miss.
15. O que é write-through cache?
✅ Correta! Cache onde escritas vão para o cache E para o banco simultaneamente.
16. O que é write-behind cache?
✅ Correta! Cache onde escritas vão para o cache e são persistidas assincronamente.
17. O que é CDN (Content Delivery Network)?
✅ Correta! Rede de servidores distribuídos que entrega conteúdo com baixa latência.
18. O que é load balancer?
✅ Correta! Componente que distribui tráfego entre múltiplos servidores.
19. O que é sharding (particionamento)?
✅ Correta! Divisão horizontal dos dados entre múltiplos bancos.
20. O que é read replica?
✅ Correta! Cópia do banco de dados usada apenas para leituras (offload do primário).
21. O que é eventual consistency?
✅ Correta! Garantia que o sistema se tornará consistente eventualmente.
22. O que é strong consistency?
✅ Correta! Garantia que todos os leituras veem a versão mais recente dos dados.
23. O que é rate limiting?
✅ Correta! Controle de requisições por cliente para evitar abuso.
24. O que é circuit breaker?
✅ Correta! Padrão que interrompe chamadas a serviços falhos para evitar cascatas.
25. O que é retry com backoff?
✅ Correta! Padrão onde tentativas falhas são repetidas com tempo de espera crescente.
