🔒 Segurança Aplicada — OWASP no Seu Código

Os ataques que realmente acontecem — injeção, XSS, CSRF, auth quebrada — com o exemplo vulnerável e a correção lado a lado, mais senhas, segredos e supply chain.

1. SQL Injection — O Clássico Eterno

// VULNERÁVEL: concatenação
db.query("SELECT * FROM users WHERE email = '" + email + "'");
// entrada: ' OR '1'='1  - retorna TODOS os usuários
// CORRETO: parâmetros (o driver separa código de dados)
db.query("SELECT * FROM users WHERE email = $1", [email]);

⚠️ Regra absoluta: dados nunca viram código.

  • Queries parametrizadas/ORM sempre
  • Valide entrada como defesa extra, não como única

2. XSS e CSRF

XSS (Cross-Site Scripting)

  • Entrada do usuário renderizada como HTML executa script no navegador da vítima
  • Defesa: escape na saída (frameworks modernos fazem por padrão)
  • Não desligue com dangerouslySetInnerHTML / v-html sem sanitizar
  • Content-Security-Policy, cookies HttpOnly

CSRF (Cross-Site Request Forgery)

  • Site malicioso faz o navegador logado disparar POST /transfer no seu app
  • Defesa: token anti-CSRF por sessão + SameSite=Lax/Strict no cookie
  • APIs por token no header (não cookie) são naturalmente menos expostas

3. Senhas, Segredos e Supply Chain

Senhas

  • Nunca em claro
  • Nunca MD5/SHA1 puros (rápidos = força bruta fácil)
  • Use bcrypt/argon2 (lentos e com salt por design)
  • Login com resposta homogênea ("credenciais inválidas")
  • Rate limit no login

Segredos

  • Fora do código e do repositório — variáveis de ambiente/secret manager
  • Rotação de segredos
  • ⚠️ Commitou segredo? Troque o segredo (o histórico do Git lembra)

📝 Exercícios — 25 questões

1. Explique por que WHERE id = ${req.params.id} é vulnerável mesmo id "sendo número".
✅ Correta! Nada garante que é número: 1; DROP TABLE users entra como código — parametrize sempre.
2. Um comentário de blog imprime <script> no navegador de quem lê. Nomeie o ataque e duas defesas.
✅ Correta! Stored XSS; escape na renderização + CSP (+ sanitização de HTML permitido).
3. Por que bcrypt e não SHA-256 para senha? (Duas razões.)
✅ Correta! Lento por design (custo de força bruta) e salt embutido (rainbow tables inúteis).
4. SameSite=Lax protege contra o quê, exatamente?
✅ Correta! Envio automático do cookie em requisições cross-site (o motor do CSRF).
5. Faça o mini threat model (4 perguntas) do endpoint de webhook de pagamento do cap. 19.
✅ Correta! Ex.: validar assinatura do gateway, idempotência por event_id, rate limit, segredo de webhook rotacionável, logs sem PII.
6. O que é OWASP Top 10?
✅ Correta! Lista dos 10 riscos de segurança mais críticos para aplicações web.
7. O que é SQL Injection?
✅ Correta! Ataque onde dados maliciosos são inseridos em queries SQL.
8. O que é XSS (Cross-Site Scripting)?
✅ Correta! Ataque onde scripts maliciosos são injetados em páginas web.
9. O que é CSRF (Cross-Site Request Forgery)?
✅ Correta! Ataque onde um site malicioso força o navegador a fazer requisições não autorizadas.
10. O que é bcrypt?
✅ Correta! Algoritmo de hashing para senhas, lento por design e com salt.
11. O que é argon2?
✅ Correta! Algoritmo moderno de hashing para senhas, vencedor do Password Hashing Competition.
12. O que é salt em hashing?
✅ Correta! Valor aleatório adicionado à senha antes do hash para evitar rainbow tables.
13. O que é rainbow table?
✅ Correta! Tabela pré-computada de hashes para quebrar senhas.
14. O que é Content-Security-Policy (CSP)?
✅ Correta! Header HTTP que define fontes permitidas de conteúdo (mitiga XSS).
15. O que é HttpOnly em cookies?
✅ Correta! Cookie que não pode ser acessado via JavaScript (mitiga XSS).
16. O que é Secure em cookies?
✅ Correta! Cookie enviado apenas via HTTPS.
17. O que é JWT e como usá-lo com segurança?
✅ Correta! JSON Web Token: use HTTPS, vida curta, assinatura forte, não guarde segredos no payload.
18. O que é OAuth2?
✅ Correta! Framework de autorização que permite delegação de acesso sem compartilhar credenciais.
19. O que é OIDC (OpenID Connect)?
✅ Correta! Camada de identidade sobre OAuth2 (autenticação + autorização).
20. O que é supply chain attack?
✅ Correta! Ataque via dependências ou ferramentas da cadeia de desenvolvimento (ex: pacotes NPM maliciosos).
21. O que é threat modeling?
✅ Correta! Processo de identificar ameaças e vulnerabilidades em um sistema.
22. O que é least privilege?
✅ Correta! Princípio onde cada componente tem apenas as permissões mínimas necessárias.
23. O que é security hardening?
✅ Correta! Processo de fortalecer a segurança de um sistema (patches, configurações).
24. O que é CORS?
✅ Correta! Cross-Origin Resource Sharing: mecanismo que permite ou restringe requisições cross-origin.
25. O que é HTTPS?
✅ Correta! HTTP + TLS: comunicação criptografada entre cliente e servidor.
