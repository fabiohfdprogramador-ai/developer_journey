🌍 Sistemas Distribuídos — O Chão de Verdade

As falácias da rede, CAP e consistência, replicação e particionamento, a ideia do Raft e os padrões event sourcing/CQRS — o vocabulário mínimo para projetar (e desconfiar) em escala.

1. As Falácias (A Rede NÃO é Confiável)

  • A rede falha
  • Tem latência
  • Muda de topologia
  • Perde e duplica pacotes

Corolários de projeto:

  • Timeout em tudo
  • Retry com backoff + jitter (e idempotência, senão o retry vira arma)
  • Circuit breaker para não afogar dependência doente

💡 A pergunta-mestra: "o que acontece se esta chamada falhar no meio?"

2. CAP e Consistência

Numa partição de rede (P, que acontece), escolha:

  • Consistência (C): recusar responder para não mentir
  • Availability (A): responder possivelmente desatualizado

Na prática o dial é fino:

  • Consistência forte: leia o que acabou de escrever — saldo
  • Eventual: converge depois — feed, catálogo, telemetria

Escolha por operação, não por sistema.

3. Replicação e Particionamento

Replicação

  • Líder: recebe escritas, réplicas seguem o log
  • Síncrona = mais durável, mais lenta
  • Assíncrona = rápida, com lag
  • Failover: promover réplica — quem decide?

Particionamento (Sharding)

  • Dados demais para um nó → particione por hash ou faixa da chave
  • Novos problemas: hot partitions, rebalanceamento, consultas cruzando shards
  • Só particione quando os números mandarem

4. Consenso — A Ideia do Raft

  • Para réplicas concordarem (quem é o líder? qual a ordem do log?)
  • Raft: eleição por termos e maioria (quorum)
  • O líder replica entradas e só confirma o que a maioria gravou
  • Maioria de 3 = 2, de 5 = 3 → tolera (n-1)/2 quedas

💡 Leia o paper "In Search of an Understandable Consensus Algorithm" — foi escrito para ser legível.

5. Event Sourcing e CQRS

Event Sourcing

  • A verdade é a sequência de eventos (OrderCreated, OrderPaid...)
  • O estado atual é derivado (replay)
  • Ganhos: auditoria total, reconstrução, integração com Kafka
  • Custos: esquema de eventos evolui, snapshots, complexidade

CQRS

  • Separar escrita (comandos, consistente) de leitura (projeções desnormalizadas, rápidas)
  • Poderoso e caro — adote quando a dor for concreta

📝 Exercícios — 25 questões

1. Retry sem jitter derrubou a dependência que voltava do incidente. Explique (thundering herd) e corrija.
✅ Correta! Todos os clientes re-tentam sincronizados na volta → pico mata de novo; backoff exponencial + jitter espalha.
2. Saldo bancário e contador de curtidas: que consistência para cada e por quê?
✅ Correta! Saldo: forte (mentir custa dinheiro); curtidas: eventual (convergir depois é ok).
3. Réplica assíncrona com lag de 2 s: que anomalia o usuário pode ver e como mitigar?
✅ Correta! Não ver a própria escrita; leia do líder após escrever (session stickiness) ou espere o lag.
4. Por que quorum de 5 nós é 3? O que 2 datacenters (2+2) não conseguem decidir?
✅ Correta! Maioria estrita tolera 2 quedas; 2+2 empata sem maioria numa partição — por isso o 5º voto (árbitro) em outro lugar.
5. No seu domínio, esboce 5 eventos de um agregado e o estado derivado deles.
✅ Correta! livre — critério: eventos no passado, imutáveis; estado = fold(events).
6. O que é um sistema distribuído?
✅ Correta! Sistema onde componentes estão em máquinas diferentes e se comunicam via rede.
7. O que é o CAP Theorem?
✅ Correta! Teorema que afirma que um sistema distribuído não pode garantir simultaneamente: Consistência, Disponibilidade e Tolerância a Partições.
8. O que é consistência forte?
✅ Correta! Todas as leituras veem a versão mais recente dos dados.
9. O que é consistência eventual?
✅ Correta! O sistema se tornará consistente eventualmente, mas não imediatamente.
10. O que é replicação?
✅ Correta! Cópia dos dados em múltiplos nós para redundância e disponibilidade.
11. O que é sharding (particionamento)?
✅ Correta! Divisão horizontal dos dados entre múltiplos nós.
12. O que é Raft?
✅ Correta! Algoritmo de consenso distribuído (mais fácil que Paxos).
13. O que é quorum?
✅ Correta! Número mínimo de nós necessários para tomar uma decisão.
14. O que é Event Sourcing?
✅ Correta! Padrão onde a verdade é a sequência de eventos, e o estado é derivado.
15. O que é CQRS?
✅ Correta! Command Query Responsibility Segregation: separação dos caminhos de escrita e leitura.
16. O que é circuit breaker?
✅ Correta! Padrão que interrompe chamadas a um serviço que está falhando para evitar sobrecarga.
17. O que é retry com backoff?
✅ Correta! Padrão onde tentativas falhas são repetidas com tempo de espera crescente.
18. O que é jitter em retries?
✅ Correta! Variação aleatória no tempo de espera para evitar thundering herd.
19. O que é thundering herd?
✅ Correta! Quando muitos clientes tentam se reconectar simultaneamente após uma falha, causando um pico.
20. O que é split brain?
✅ Correta! Situação onde dois nós acreditam ser o líder em um sistema distribuído.
21. O que é idempotência?
✅ Correta! Propriedade onde a operação pode ser repetida sem efeitos colaterais diferentes.
22. O que é exactly-once?
✅ Correta! Garantia que uma mensagem é processada exatamente uma vez (na prática = at-least-once + idempotência).
23. O que é at-least-once?
✅ Correta! Garantia que a mensagem será entregue pelo menos uma vez (pode ter duplicatas).
24. O que é at-most-once?
✅ Correta! Garantia que a mensagem será entregue no máximo uma vez (pode ser perdida).
25. O que é consenso em sistemas distribuídos?
✅ Correta! Processo onde múltiplos nós chegam a um acordo sobre um valor ou decisão.
