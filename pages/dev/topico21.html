🐳 Docker — Empacotando de Verdade

Imagem × container, um Dockerfile multi-stage exemplar e as práticas que separam imagem de 1 GB insegura de imagem de 20 MB de produção.

1. O Modelo

  • Imagem = sistema de arquivos em camadas + metadados (imutável)
  • Container = processo isolado rodando a partir da imagem
  • Namespaces = visão própria de processos/rede/arquivos
  • Cgroups = limites de CPU/RAM (o kernel do cap. 14 em ação)
  • Registry = guarda imagens versionadas

💡 Container não é VM — compartilha o mesmo kernel do host.

2. Multi-stage Exemplar (Go)

FROM golang:1.22 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download  # camada cacheável: deps mudam pouco
COPY . .
RUN CGO_ENABLED=0 go build -o /out/app ./cmd/api

# --- runtime ---
FROM gcr.io/distroless/static
COPY --from=build /out/app /app
USER nonroot
ENTRYPOINT ["/app"]

Resultado: imagem final de ~15 MB, sem compilador, sem shell, não-root.

3. Práticas

  • Ordene o Dockerfile do que menos muda para o que mais muda (cache de camadas)
  • .dockerignore
  • Uma responsabilidade por container
  • Logs no stdout
  • Config por variável de ambiente
  • Tags imutáveis (nada de :latest em produção)
docker build -t api:1.4.2 .
docker run -p 8080:8080 --rm api:1.4.2
docker compose up -d  # app + postgres + redis no dev

📝 Exercícios — 25 questões

1. Por que copiar go.mod e rodar go mod download antes de copiar o código?
✅ Correta! Cache: código muda todo commit; dependências não — build 10× mais rápido.
2. Container é VM? Explique com namespaces/cgroups.
✅ Correta! Não: processos no MESMO kernel com visão e limites isolados; VM tem kernel próprio.
3. Três motivos para distroless/alpine no estágio final.
✅ Correta! Tamanho, superfície de ataque, startup.
4. Sua imagem tem 1,2 GB. Liste 4 suspeitos e a correção de cada.
✅ Correta! Estágio único com toolchain (→ multi-stage); base gorda (→ distroless); sem .dockerignore (→ criar); artefatos de build/teste copiados (→ copiar só o binário/dist).
5. O que é Dockerfile?
✅ Correta! Arquivo com instruções para construir uma imagem Docker.
6. O que é imagem Docker?
✅ Correta! Pacote imutável com tudo necessário para rodar uma aplicação (código, runtime, dependências).
7. O que é container Docker?
✅ Correta! Instância em execução de uma imagem Docker.
8. O que é Docker Hub?
✅ Correta! Registry público de imagens Docker.
9. O que é docker compose?
✅ Correta! Ferramenta para definir e rodar aplicações multi-container.
10. O que é camada (layer) em imagens Docker?
✅ Correta! Cada instrução no Dockerfile cria uma camada imutável; camadas são cacheadas e reutilizadas.
11. O que é multi-stage build?
✅ Correta! Técnica que usa múltiplos estágios no Dockerfile para construir e depois copiar apenas o necessário para a imagem final.
12. O que é .dockerignore?
✅ Correta! Arquivo que especifica quais arquivos não devem ser copiados para o contexto de build.
13. O que é ENTRYPOINT no Dockerfile?
✅ Correta! Comando executado quando o container inicia.
14. O que é CMD no Dockerfile?
✅ Correta! Comando padrão que pode ser sobrescrito ao rodar o container.
15. O que é COPY no Dockerfile?
✅ Correta! Copia arquivos do host para a imagem.
16. O que é ADD no Dockerfile?
✅ Correta! Similar ao COPY, mas também pode extrair arquivos tar e baixar URLs.
17. O que é RUN no Dockerfile?
✅ Correta! Executa comandos durante a construção da imagem.
18. O que é ENV no Dockerfile?
✅ Correta! Define variáveis de ambiente na imagem.
19. O que é EXPOSE no Dockerfile?
✅ Correta! Documenta que o container escuta em uma porta específica.
20. O que é VOLUME no Dockerfile?
✅ Correta! Define um ponto de montagem para volumes persistentes.
21. O que é docker build?
✅ Correta! Comando que constrói uma imagem a partir de um Dockerfile.
22. O que é docker run?
✅ Correta! Comando que cria e inicia um container a partir de uma imagem.
23. O que é docker ps?
✅ Correta! Comando que lista containers em execução.
24. O que é docker stop?
✅ Correta! Comando que para um container em execução.
25. O que é docker rm?
✅ Correta! Comando que remove um container parado.
