📦 Git de Verdade

Snapshots, branches baratos, merge x rebase e o fluxo de Pull Request — seu GitHub é seu currículo.

1. O Modelo Mental

Git guarda snapshots do projeto (commits), cada um apontando para o anterior — um grafo. Uma branch é só um ponteiro móvel para um commit; criar branch custa nada.

Três áreas:

  • Working directory — seus arquivos atuais
  • Staging — o que vai entrar no próximo commit
  • Repository — histórico permanente
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Working   │ → │   Staging   │ → │  Repository │
│  Directory  │    │    Area     │    │  (History)  │
└─────────────┘    └─────────────┘    └─────────────┘
     (arquivos)       (git add)          (git commit)

2. O Ciclo Diário

git status                    # sempre: onde estou, o que mudou
git add src/app.js           # escolhe o que entra
git add -p                   # staging por trecho (poderoso!)
git commit -m "feat: valida email no cadastro"
git log --oneline --graph    # o grafo do projeto
git diff                     # o que mudou (não staged)
git diff --staged            # o que está no staging

3. Branches, Merge e Rebase

git switch -c feat/login      # cria e muda para a branch
git switch main && git pull   # atualiza a main
git merge feat/login          # junta criando commit de merge
git rebase main               # reaplica seus commits sobre a main

Merge

Preserva a história como aconteceu. Bom para juntar trabalho compartilhado.

Rebase

Reescreve sua branch para uma história linear. Bom antes do PR.

⚠️ Regra de Ouro

Nunca rebase commits já publicados/compartilhados.

Conflito não é erro, é decisão

<<<<<<< HEAD
console.log("versão antiga")
=======
console.log("versão nova")
>>>>>>> feat/login

Abra o arquivo, escolha, git add e continue.

4. Trabalhando com Remotos e PRs

git clone git@github.com:voce/projeto.git
git push -u origin feat/login        # publica a branch
# → abra o Pull Request na interface
# Descreva O QUÊ e POR QUÊ
git fetch && git log origin/main..main  # o que você tem que o remoto não tem

Fluxo profissional: branch pequena → commits limpos → PR com descrição → review → merge na main.

PRs pequenos (< 400 linhas) recebem revisões melhores e entram mais rápido.

5. Kit de Sobrevivência

git stash                     # guarda mudanças temporariamente
git stash pop                 # devolve as mudanças
git restore arquivo           # descarta mudança local
git revert <hash>             # desfaz um commit (seguro em público)
git reset --hard HEAD~1       # apaga o último commit LOCAL (cuidado!)
git reflog                    # a máquina do tempo: encontra "commits perdidos"

6. Antipadrões que Denunciam Iniciante

  • ❌ Commit gigante "ajustes finais"
  • ❌ Trabalhar direto na main
  • ❌ git push -f em branch compartilhada
  • ❌ Repositório sem README
  • ❌ Segredos commitados (senha em código — trocar a senha, não só apagar o arquivo)

📝 Exercícios — 25 questões

1. Qual a diferença entre working directory, staging e repository?
✅ Correta! Arquivos reais → seleção do próximo commit → histórico permanente.
2. Você fez 3 commits na feature e a main andou. Que comando deixa sua branch linear sobre a main?
✅ Correta! git rebase main (na feature)
3. Commitou um erro já publicado na main. Comando seguro para desfazer?
✅ Correta! git revert <hash> — cria commit inverso sem reescrever história.
4. Para que serve git add -p e por que ele melhora seus commits?
✅ Correta! Staging por trecho: permite commits atômicos e mensagens honestas.
5. Monte o fluxo completo (comandos) de: criar branch, commitar, publicar e preparar o PR.
✅ Correta! git switch -c feat/x → git add -p → git commit -m "..." → git push -u origin feat/x → abrir PR
6. git reflog te salva em qual situação clássica?
✅ Correta! Recuperar commit "perdido" após reset/rebase errado.
7. Como ver o que mudou e ainda não foi adicionado ao staging?
✅ Correta! git diff
8. Como ver o que já está no staging?
✅ Correta! git diff --staged
9. Como desfazer alterações locais em um arquivo específico?
✅ Correta! git restore arquivo
10. Como guardar mudanças temporariamente sem commitar?
✅ Correta! git stash
11. Como recuperar mudanças guardadas com stash?
✅ Correta! git stash pop
12. Qual comando mostra o grafo de commits de forma compacta?
✅ Correta! git log --oneline --graph
13. O que é uma branch no Git?
✅ Correta! Um ponteiro móvel para um commit.
14. Por que nunca se deve fazer git push -f em branch compartilhada?
✅ Correta! Reescreve a história publicada, quebrando o trabalho de quem já está na branch.
15. Como atualizar sua branch main com as mudanças do remoto?
✅ Correta! git switch main && git pull
16. Qual a diferença entre merge e rebase?
✅ Correta! Merge preserva a história real; rebase reescreve para uma história linear.
17. Como resolver um conflito de merge?
✅ Correta! Editar os arquivos com os marcadores <<<<<<< e >>>>>>>, depois git add e continuar.
18. Como criar e mudar para uma nova branch ao mesmo tempo?
✅ Correta! git switch -c nome-da-branch
19. Como ver quais commits você tem localmente que o remoto não tem?
✅ Correta! git log origin/main..main
20. O que fazer se você commitou um segredo (senha) no repositório?
✅ Correta! Trocar o segredo imediatamente (o histórico do Git lembra mesmo após apagar).
21. Como desfazer o último commit mantendo as mudanças no working directory?
✅ Correta! git reset --soft HEAD~1
22. Como desfazer o último commit descartando as mudanças?
✅ Correta! git reset --hard HEAD~1 (cuidado: perde as mudanças)
23. O que significa uma mensagem de commit bem escrita?
✅ Correta! Imperativo curto + explicação do porquê no corpo quando necessário.
24. Por que PRs pequenos são melhores?
✅ Correta! Recebem revisões melhores e são aprovados mais rápido (< 400 linhas).
25. Como listar todos os branches (locais e remotos)?
✅ Correta! git branch -a
