⚡ Performance — Método, Não Adivinhação

O ritual profissional: medir por percentis, achar o gargalo com profiling, atacar com a alavanca certa (quase sempre cache ou I/O) e provar o ganho.

1. O Ritual

  1. Defina a meta (SLO: p95 < 300 ms no checkout)
  2. Meça em produção (RED do cap. 24) — intuição não é dado
  3. Profile para achar o gargalo: CPU/heap com pprof, flamegraphs, EXPLAIN ANALYZE
  4. Otimize UMA coisa, a maior
  5. Meça de novo e escreva o antes/depois

⚠️ Sem o passo 5, foi fé, não engenharia.

Lei de Amdahl: otimizar 5% do tempo total rende no máximo 5%.

2. As Alavancas Usuais (em ordem de frequência)

Banco

  • Consulta N+1 (100 queries onde cabia 1 JOIN)
  • Índice faltando
  • SELECT * gordo

Cache em Camadas

  • Memória local → Redis → CDN
  • Cache-aside: lê do cache; miss → busca, popula com TTL
  • Parte difícil: invalidação (TTL curto + invalidação por evento)
  • Cuidado com hot key e stampede (lock/single-flight no miss)

Concorrência e Batching

  • Paralelize I/O independente
  • Agrupe escritas
  • Backpressure: fila limitada + rejeitar cedo

Alocações e Serialização

  • Menos JSON gigante, menos cópias, buffers reusados

3. Exemplo Resolvido — O Endpoint de 900 ms

p95 de 900 ms no GET /dashboard. Trace mostra: 12 queries (N+1 por widget) + serialização de 2 MB.

Ações:

  1. 1 query com JOIN + projeção dos campos usados (~600 ms)
  2. Cache Redis de 30 s no agregado (~200 ms no hit)

Resultado medido: p95 = 110 ms

📝 Exercícios — 25 questões

1. Por que p99 importa mais que média num e-commerce? Dê o exemplo numérico do cap. 24.
✅ Correta! 1% dos checkouts lentos = clientes reais perdidos; média esconde a cauda (p50 80 ms, p99 2 s).
2. Detecte o N+1: pedidos = repo.list(); for p in pedidos: p.cliente = repo.cliente(p.id_cliente). Corrija.
✅ Correta! 1 + N queries → JOIN / WHERE id IN (…) numa ida.
3. Projete o cache do GET /produto/{id}: chave, TTL, invalidação no update.
✅ Correta! prod:{id} com TTL 60 s; no update, DEL prod:{id} (invalidação por evento).
4. O que é cache stampede e como o single-flight resolve?
✅ Correta! Expirou a chave quente → mil misses simultâneos batem no banco; single-flight deixa 1 buscar e os demais esperam o resultado.
5. Sua API aguenta 1.000 req/s e chegam 5.000: por que fila ilimitada é pior que rejeitar com 429?
✅ Correta! Fila infinita = latência infinita e OOM; rejeitar cedo preserva quem dá para atender (backpressure).
6. O que é profiling?
✅ Correta! Análise do comportamento de um programa (CPU, memória, alocações) para encontrar gargalos.
7. O que é flamegraph?
✅ Correta! Visualização de profiling onde a largura mostra onde o tempo é gasto.
8. O que é pprof?
✅ Correta! Ferramenta de profiling para Go (CPU, memória, alocações).
9. O que é cache stampede?
✅ Correta! Múltiplas requisições simultâneas para um cache expirado, todas batendo no banco.
10. O que é single-flight?
✅ Correta! Padrão onde apenas uma requisição executa e as demais esperam o resultado.
11. O que é backpressure?
✅ Correta! Mecanismo que rejeita requisições quando o sistema está sobrecarregado.
12. O que é Lei de Amdahl?
✅ Correta! O ganho de performance é limitado pela fração do código que foi otimizada.
13. O que é N+1 problem?
✅ Correta! 1 query para listar + N queries para detalhes de cada item.
14. O que é cache-aside?
✅ Correta! Padrão onde a aplicação consulta o cache primeiro; se miss, busca no banco e popula.
15. O que é TTL em cache?
✅ Correta! Time To Live: tempo de vida de um item no cache.
16. O que é hot key?
✅ Correta! Chave em cache que é acessada frequentemente por muitos usuários.
17. O que é memory leak?
✅ Correta! Memória alocada que nunca é liberada, consumindo recursos.
18. O que é garbage collection (GC)?
✅ Correta! Coletor de lixo que libera memória automaticamente em linguagens como Go, Java.
19. O que é benchmark?
✅ Correta! Teste para medir performance de um sistema ou componente.
20. O que é latência?
✅ Correta! Tempo de resposta de uma requisição.
21. O que é throughput?
✅ Correta! Quantidade de requisições processadas por unidade de tempo.
22. O que é percentil?
✅ Correta! Valor abaixo do qual X% das observações se encontram.
23. O que é query N+1?
✅ Correta! Problema onde N+1 queries são executadas onde 1 seria suficiente (usando JOIN).
24. O que é EXPLAIN ANALYZE?
✅ Correta! Comando PostgreSQL que mostra o plano de execução e estatísticas reais de uma query.
25. O que é cache miss?
✅ Correta! Quando o dado não está no cache e precisa ser buscado na fonte original.
