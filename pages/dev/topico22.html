☸️ Kubernetes — O Essencial que Resolve 90%

O modelo declarativo e os 6 objetos do dia a dia — Deployment, Pod, Service, Ingress, ConfigMap/Secret — com probes e requests/limits bem postos.

1. O Modelo Mental

  • Você declara o estado desejado (YAML)
  • Controladores reconciliam o mundo real até bater (loop de reconciliação)
  • Kubelet: roda pods nos nós
  • Scheduler: decide onde cabe

2. O YAML Canônico

apiVersion: apps/v1
kind: Deployment
metadata: { name: api }
spec:
  replicas: 3
  selector: { matchLabels: { app: api } }
  template:
    metadata: { labels: { app: api } }
    spec:
      containers:
      - name: api
        image: registry.io/api:1.4.2
        ports: { containerPort: 8080 }
        envFrom:
        - configMapRef: { name: api-config }
        - secretRef: { name: api-secrets }
        resources:
          requests: { cpu: "100m", memory: "128Mi" }   # para agendar
          limits: { cpu: "500m", memory: "256Mi" }     # teto (OOMkill)
        readinessProbe: { httpGet: { path: /ready, port: 8080 } }
        livenessProbe: { httpGet: { path: /live, port: 8080 } }
---
apiVersion: v1
kind: Service
metadata: { name: api }
spec:
  selector: { app: api }
  ports: { port: 80, targetPort: 8080 }
  • Pod: 1+ containers com rede/volume compartilhados
  • Deployment: mantém N réplicas e faz rolling update
  • Service: IP/DNS estável na frente dos pods
  • Ingress: roteia HTTP externo
  • ConfigMap/Secret: config fora da imagem

3. Probes

  • readiness = "posso receber tráfego?" (tira do balanceador sem matar)
  • liveness = "estou vivo?" (reinicia se travar)

⚠️ Confundir os dois causa cascatas de restart.

📝 Exercícios — 25 questões

1. Por que apontar clientes para o Service e nunca para IP de pod?
✅ Correta! Pods morrem e trocam de IP; o Service é o endereço estável com balanceamento.
2. Pod em CrashLoopBackOff: seus três primeiros comandos?
✅ Correta! kubectl logs (ou --previous), kubectl describe pod (eventos), conferir probes/env/imagem.
3. Readiness x liveness: o que acontece se você usar liveness onde era readiness (ex.: dependência externa fora)?
✅ Correta! Reinícios em massa por causa de dependência externa — derruba tudo em cascata; readiness só tiraria do tráfego.
4. Sem requests, o que o scheduler não consegue fazer? Sem limits, qual o risco?
✅ Correta! Agendar com critério (bin packing); sem limites, um vizinho barulhento esfomeia o nó.
5. Escreva o Ingress (esboço) para api.exemplo.com → Service api:80.
✅ Correta! kind Ingress com rule host api.example.com, path /, backend service api porta 80 (+ TLS via secret).
6. O que é Kubernetes?
✅ Correta! Orquestrador de containers para automação de deploy, scaling e gerenciamento.
7. O que é um Pod?
✅ Correta! Menor unidade do K8s: um ou mais containers com rede e volume compartilhados.
8. O que é um Deployment?
✅ Correta! Controlador que gerencia réplicas de Pods com rolling updates e rollbacks.
9. O que é um Service?
✅ Correta! Abstração que expõe Pods como um serviço de rede estável.
10. O que é um Ingress?
✅ Correta! Objeto que gerencia acesso externo HTTP/HTTPS aos serviços.
11. O que é ConfigMap?
✅ Correta! Armazena dados de configuração em formato chave-valor.
12. O que é Secret?
✅ Correta! Armazena dados sensíveis como senhas, tokens, chaves SSH.
13. O que é kubectl?
✅ Correta! CLI para gerenciar clusters Kubernetes.
14. O que é kubelet?
✅ Correta! Agente que roda em cada nó e garante que os containers estejam em execução.
15. O que é scheduler?
✅ Correta! Componente que decide em qual nó um Pod vai rodar.
16. O que é namespace no Kubernetes?
✅ Correta! Isolamento lógico de recursos dentro do cluster.
17. O que é Horizontal Pod Autoscaler (HPA)?
✅ Correta! Auto-scaling baseado em métricas (CPU, memória, custom).
18. O que é readinessProbe?
✅ Correta! Verifica se o container está pronto para receber tráfego.
19. O que é livenessProbe?
✅ Correta! Verifica se o container está vivo (reinicia se falhar).
20. O que é rolling update?
✅ Correta! Atualização gradual de Pods, substituindo um por um, sem downtime.
21. O que é rollback no Kubernetes?
✅ Correta! Reverte um deployment para uma versão anterior.
22. O que é PersistentVolume (PV)?
✅ Correta! Recurso de armazenamento persistente no cluster.
23. O que é PersistentVolumeClaim (PVC)?
✅ Correta! Solicitação de armazenamento por um Pod.
24. O que é etcd no Kubernetes?
✅ Correta! Banco de dados distribuído que armazena o estado do cluster.
25. O que é kube-api-server?
✅ Correta! Componente central que expõe a API do Kubernetes.
