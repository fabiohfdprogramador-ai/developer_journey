🗄️ SQL e PostgreSQL a Fundo

Modelar, consultar com joins e agregações, indexar com critério e entender transações — usando o PostgreSQL como universidade de dados.

1. Modelagem

CREATE TABLE customers (
    id BIGSERIAL PRIMARY KEY,
    email TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    created_at TIMESTAMP2 NOT NULL DEFAULT now()
);

CREATE TABLE orders (
    id BIGSERIAL PRIMARY KEY,
    customer_id BIGINT NOT NULL REFERENCES customers(id),
    status TEXT NOT NULL CHECK (status IN ('new','paid','shipped','canceled')),
    total_cents BIGINT NOT NULL,
    created_at TIMESTAMP2 NOT NULL DEFAULT now()
);
  • Primary key: estável, única
  • Foreign key: integridade no banco, não na aplicação
  • Dinheiro: inteiros de centavos (evite float)
  • Timestamp: sempre use TIMESTAMP WITH TIME ZONE
  • Normalize até doer, desnormalize onde medir

2. Consultas que Pagam o Salário

-- Filtro + Ordenação + Paginação
SELECT id, name
FROM customers
WHERE created_at >= now() - interval '30 days'
ORDER BY created_at DESC
LIMIT 20;

-- JOIN: pedidos com o nome do cliente
SELECT o.id, c.name, o.total_cents
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.status = 'paid';

-- Agregação: receita por cliente
SELECT c.name, SUM(o.total_cents)/100.0 AS receita
FROM orders o
JOIN customers c ON c.id = o.customer_id
GROUP BY c.name
HAVING SUM(o.total_cents) > 50000
ORDER BY receita DESC;
  • JOINs: INNER (só casados), LEFT (todos da esquerda + pares)
  • WHERE filtra linhas antes de agrupar; HAVING filtra grupos
  • Window functions: ROW_NUMBER() OVER (...)
  • CTEs: WITH recentes AS (...) SELECT ...

3. Índices — O log n Aplicado

CREATE INDEX idx_orders_customer ON orders (customer_id);
CREATE INDEX idx_orders_status_created ON orders (status, created_at);
  • Indexe o que o WHERE/JOIN/ORDER BY usa
  • Índice composto serve prefixos: (status, created_at) atende status= e status= AND created_at>
  • Cada escrita atualiza os índices — indexar tudo deixa o INSERT de joelhos

EXPLAIN ANALYZE

EXPLAIN ANALYZE SELECT ...;
  • Seq Scan = leu a tabela toda
  • Index Scan = usou a árvore

4. Transações e ACID

BEGIN;
UPDATE contas SET saldo = saldo - 100 WHERE id = 1;
UPDATE contas SET saldo = saldo + 100 WHERE id = 2;
COMMIT;  -- ou ROLLBACK: tudo ou nada
  • Atomicity: tudo ou nada
  • Consistency: estado válido antes e depois
  • Isolation: concorrência isolada
  • Durability: persistente após commit

MVCC: leituras consistentes sem bloquear escritas.

📝 Exercícios — 25 questões

1. Escreva a consulta: os 10 clientes com mais pedidos 'paid' nos últimos 90 dias.
✅ Correta! JOIN + WHERE status/data + GROUP BY cliente + ORDER BY COUNT() DESC LIMIT 10.
2. Por que total_cents BIGINT e não total NUMERIC(10,2) ou float?
✅ Correta! Centavos inteiros: exatos e rápidos; float erra centavos (IEEE 754); NUMERIC é exato porém mais lento.
3. A consulta WHERE email = 'x@y.com' está lenta com 5 milhões de clientes. Diagnóstico e correção?
✅ Correta! EXPLAIN mostrará Seq Scan; o UNIQUE em email já cria índice — se não existisse, CREATE INDEX ON customers(email).
4. O índice (status, created_at) atende WHERE created_at > now() - interval '1 day'? Por quê?
✅ Correta! Não — created_at não é prefixo do índice.
5. Modele a transferência entre carteiras com proteção contra saldo negativo (constraint + transação).
✅ Correta! CHECK (saldo >= 0) + BEGIN/2 UPDATES/COMMIT (o CHECK aborta a transação se negativar).
6. O que MVCC permite que um esquema de locks puros não permite?
✅ Correta! Leituras consistentes sem bloquear escritas (e vice-versa).
7. O que é JOIN em SQL?
✅ Correta! Combina registros de duas ou mais tabelas baseado em uma condição.
8. Qual a diferença entre INNER JOIN e LEFT JOIN?
✅ Correta! INNER: só registros que casam; LEFT: todos da esquerda + casamentos da direita (NULL se não casar).
9. O que é GROUP BY?
✅ Correta! Agrupa registros que têm os mesmos valores para aplicar funções de agregação.
10. Qual a diferença entre WHERE e HAVING?
✅ Correta! WHERE filtra linhas antes do GROUP BY; HAVING filtra grupos depois do GROUP BY.
11. O que é PRIMARY KEY?
✅ Correta! Chave que identifica unicamente cada registro na tabela.
12. O que é FOREIGN KEY?
✅ Correta! Chave que referencia a PRIMARY KEY de outra tabela (integridade referencial).
13. O que é índice em banco de dados?
✅ Correta! Estrutura que acelera buscas (ex: B-tree) ao custo de escritas mais lentas.
14. O que é transação ACID?
✅ Correta! Sequência de operações executada como unidade atômica, consistente, isolada e durável.
15. O que é MVCC (Multi-Version Concurrency Control)?
✅ Correta! Mecanismo que mantém múltiplas versões de um registro para permitir leituras consistentes sem bloquear escritas.
16. O que é normalização?
✅ Correta! Processo de organizar dados para reduzir redundância e melhorar integridade.
17. O que é desnormalização?
✅ Correta! Introdução controlada de redundância para melhorar performance de leitura.
18. O que é EXPLAIN em PostgreSQL?
✅ Correta! Mostra o plano de execução de uma consulta — como o banco vai executá-la.
19. Qual a diferença entre CHAR e VARCHAR?
✅ Correta! CHAR: tamanho fixo (completa com espaços); VARCHAR: tamanho variável.
20. O que é B-tree no contexto de índices?
✅ Correta! Árvore balanceada usada em índices para buscas O(log n).
21. O que é VIEW (visão) no banco de dados?
✅ Correta! Consulta SQL armazenada que se comporta como uma tabela virtual.
22. O que é materialized view?
✅ Correta! View que armazena fisicamente os resultados (mais rápida para consultas).
23. O que é CTE (Common Table Expression)?
✅ Correta! Tabela temporária dentro de uma consulta, criada com WITH.
24. O que é WAL (Write-Ahead Log) no PostgreSQL?
✅ Correta! Log que registra mudanças antes de serem aplicadas ao disco (durabilidade e recuperação).
25. O que é vacuum no PostgreSQL?
✅ Correta! Processo que limpa registros mortos (deletados/atualizados) e recupera espaço.
